# Evidence and privacy policy

Use one explicit evidence status for each record:

| Status | Meaning |
| --- | --- |
| Simulation | Invented scenario or illustrative observation; no execution claimed |
| Lab result | Actually performed in an authorised lab with dated supporting evidence |
| Work in progress | Incomplete investigation; state completed steps and unresolved questions |

All tickets currently have Simulation status. There are no genuine troubleshooting outputs in this repository.

For an actual lab result, record date/time and timezone, environment and versions, collection method, expected behaviour, observed behaviour, interpretation and limitations. Preserve original evidence privately where appropriate and publish only a reviewed redacted copy. Record transformations; do not silently alter output to make it look successful.

Never publish client names, email addresses, telephone numbers, tenant IDs, secrets, tokens, serial numbers, real public IPs, customer call recordings or unreviewed configurations. Browser HARs, packet captures, command transcripts and screenshots can contain credentials and personal information. Do not upload real client material simply because names were removed.

Use fictional identities and example domains for simulations. Do not fabricate screenshots, vendor verdicts, completed incident responses, uptime improvements or response metrics. A closed alert is not proof of eradication; an empty query is not proof that no activity occurred.

This policy applies to newly added content. It does not certify the privacy or provenance of files in other repositories.
